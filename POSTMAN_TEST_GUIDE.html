📌 Base URL: http://localhost:8080

1. AUTENTICACIÓN
POST /api/auth/login

🔐 Obtener token JWT para acceder a los endpoints protegidos

📤 Request Body:

{ "username": "admin", "password": "admin123" }

📥 Response Esperado (200 OK):

{ "token": "eyJhbGciOiJIUzUxMiJ9...", "user": { "id": 1, "username": "admin", "email": "admin@app.com", "role": "ADMIN", "active": true, "createdAt": "2025-11-18T01:18:36..." } }
⚠️ Importante: Copia el valor del campo token para usarlo en las siguientes pruebas. Este token se utiliza en el header Authorization: Bearer <token>

6. CONFIGURACIÓN EN POSTMAN

Paso 1: Configurar el Token JWT

  1. Abre Postman y crea una nueva petición
  2. Ve a POST → Ingresa la URL: http://localhost:8080/api/auth/login
  3. En la pestaña Body, selecciona raw y JSON
  4. Pega el siguiente JSON:
    { "username": "admin", "password": "admin123" }
  5. Haz clic en Send
  6. Copia el valor del campo "token" de la respuesta

Paso 2: Usar el Token en tus Peticiones

  1. En cualquier petición que requiera autenticación:
  2. Ve a la pestaña Headers
  3. Agrega una nueva cabecera:
    Key: Authorization Value: Bearer <tu_token_aqui>
  4. Reemplaza <tu_token_aqui> con el token que copiaste

Paso 3: Usar Variables de Ambiente (Recomendado)

  1. En Postman, haz clic en el ícono de engranaje ⚙️ en la esquina superior derecha
  2. Selecciona Manage Environments
  3. Haz clic en Create
  4. Agrega las siguientes variables:
Variable Valor Inicial Descripción
base_url http://localhost:8080 URL base del servidor
token {{token_aqui}} Token JWT (se actualiza después del login)
admin_user admin Usuario administrador para login
admin_pass admin123 Contraseña administrador
💡 Tip: En Postman, puedes usar {{variable_name}} para referenciar variables. Por ejemplo: {{base_url}}/api/categories

8. CÓDIGOS DE RESPUESTA HTTP
Código Estado Descripción
200 OK La petición fue exitosa
201 Created El recurso fue creado exitosamente
400 Bad Request Error en la solicitud (datos inválidos)
401 Unauthorized Se requiere autenticación o token inválido
403 Forbidden No tienes permisos para acceder a este recurso
404 Not Found El recurso no fue encontrado
500 Server Error Error interno del servidor
9. TIPS Y SOLUCIÓN DE PROBLEMAS

❌ Error: "Connection refused"

Verifica que:
  • ✓ El servidor Spring Boot está en ejecución (en puerto 8080)
  • ✓ MySQL está ejecutándose (XAMPP iniciado)
  • ✓ La base de datos app_mobile_db existe

❌ Error: "401 Unauthorized"

Significa que:
  • ✓ Falta el header Authorization
  • ✓ El token es inválido o expiró (24 horas)
  • ✓ El formato del header es incorrecto (debe ser: Bearer <token>)

❌ Error: "403 Forbidden"

Significa que:
  • ✓ Tu usuario no tiene el rol requerido
  • ✓ El endpoint requiere rol ADMIN y estás usando COORDINADOR

❌ Error: "Column 'email' cannot be null"

Cuando creas un usuario, asegúrate que incluyas el campo email en el JSON.

✅ Buenas Prácticas

  1. Siempre verifica que el servidor esté corriendo antes de hacer peticiones
  2. Usa variables de ambiente en Postman para reutilizar valores
  3. Genera un nuevo token después de 24 horas (expiración)
  4. Lee los mensajes de error para entender qué salió mal
  5. Usa métodos GET para consultas, POST para crear, PUT para actualizar, DELETE para eliminar
